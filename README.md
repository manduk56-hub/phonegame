# 플레이룸

게임 선택 화면에서도 QR로 바로 참가할 수 있습니다. 이름을 입력해 한 번 연결한 휴대폰은 포크레인과 POCKET RACING을 바꿔도 같은 참가자로 유지되며, 조작 화면이 자동으로 전환됩니다. 경기를 마친 뒤 게임 선택으로 돌아가 다음 게임의 대기실에 입장하세요. 게임과 서버를 종료하지 않는 동안 QR을 다시 찍거나 이름을 다시 입력할 필요가 없습니다. PC 선택 화면에 현재 접속 인원도 표시됩니다.

## 인스톨러·자동 업데이트와 자동 터널 (2026-10-04)

일반 사용자는 GitHub Releases의 `Playroom-Installer.zip`을 내려받아 압축을 풀고 `Install-Playroom.cmd`를 실행합니다. 설치 위치를 선택하면 게임과 Node·Godot 실행파일·터널 프로그램을 함께 설치하고 바탕화면에 **플레이룸** 바로가기 하나를 만듭니다. 설치 화면은 설치할 때만 사용합니다. 소스 저장소에서 직접 받은 경우에도 `Install-Playroom.cmd`를 실행해 같은 설치를 진행할 수 있습니다. 소스 파일만으로는 필요한 실행 도구가 모두 설치되지 않습니다.

바탕화면의 플레이룸을 실행하면 작은 진행 창에서 GitHub Releases의 `playroom-manifest.json`을 확인합니다. 설치 버전보다 새 버전이면 다운로드 → SHA256 검사 → 패키지 내부 버전 검사 → 새 버전 활성화 → 게임 실행 순서로 자동 업데이트합니다. 업데이트 확인만 실패하면 설치된 게임을 자동으로 실행합니다. 실제 다운로드·설치가 실패하면 원인을 표시하고 **기존 버전 실행** 버튼으로 설치된 게임을 열 수 있습니다. 실패 이유는 설치 폴더의 `state/update.json`에 기록합니다. 기존 버전 폴더는 보존합니다. 이미 실행 중인 게임을 다시 실행하면 해당 게임 창을 앞으로 가져옵니다.

게임 실행 시 각 PC에 독립된 Node 서버를 빈 포트로 열고 임의의 방장 키를 생성합니다. PC별 Cloudflare Quick Tunnel 주소를 자동 발급하고 실제 외부 접속을 확인한 다음 게임과 QR을 표시합니다. 다른 Wi-Fi나 LTE의 휴대폰도 해당 QR로 참가합니다. A PC와 B PC는 서버·터널·방 코드가 달라 각각의 방으로 플레이합니다. 기존 구매 서버의 주소나 SSH 키는 일반 게임 실행에 사용하지 않습니다. 게임 서버는 방장 PC에서 실행되며 터널이 인터넷 접속을 연결합니다.

게임 종료·시작 취소 시 해당 게임·서버·터널을 함께 종료합니다. 터널 프로세스 종료 시 최대 3회 새 터널을 열고 QR을 갱신하며 방·참가자·경기를 유지합니다. 호스트 PC를 끄거나 절전 상태로 전환하면 참가할 수 없습니다. 현재 터널은 주소가 매번 바뀌는 **Cloudflare Quick Tunnel 테스트 방식**이며 서비스 가용성이 보장되지 않습니다. 공식 문서: https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/

### 개발 결과 바로 확인

레이싱은 게임 선택에서 **POCKET RACING**으로 입장합니다. 폰은 가로로 잡고 차를 선택한 뒤 **기울기 조작 시작**을 누릅니다. 센서 접근은 HTTPS 터널 QR을 사용하고, 현재 자세를 기준으로 **중립 보정**할 수 있습니다. 왼쪽은 브레이크, 오른쪽은 엑셀 페달입니다. 폰에는 자신의 1인칭 운전석이, PC에는 서킷 전체와 실시간 순위가 표시됩니다. 여섯 차종은 참조 이미지의 특징을 입체 모델로 만들었으며 선택지는 실제 모델을 렌더링합니다. 같은 차도 참가자별 색상이 다릅니다. 모든 차의 가속·최고속도·조향·제동 성능은 같고 5바퀴 완주 순서로 순위를 정합니다. 충돌과 코스 밖 감속을 사용합니다. 최대 경기 시간이 끝나면 미완주 차량은 진행 거리로 순위를 정합니다.

휴대폰 차량 선택 화면의 **주행 시점**에서 **1인칭 · 운전석** 또는 **3인칭 · 가까운 추적**을 고릅니다. 경기 중에도 상단의 **1인칭 / 3인칭** 버튼으로 즉시 전환할 수 있습니다. 3인칭은 차 중심에서 뒤로 6m, 높이 2.8m에서 내 차와 전방 코스를 따라갑니다. 3인칭에서는 운전석 대시보드와 핸들 그림을 숨기며 페달·기울기 조작은 그대로 사용할 수 있습니다. 선택은 해당 브라우저에 저장됩니다. 모바일 페이지를 새로고침하면 적용됩니다.

레이싱 서킷은 그린밸리 GP(0.68km), 아주르 하버(0.70km), 사쿠라 테크니컬(0.75km), 듄 인터내셔널(0.88km) 네 개입니다. PC 레이싱 대기실의 **서킷 선택**에서 코스 모양과 난이도를 보고 고릅니다. 웹 대기실에도 네 개의 코스 카드가 표시됩니다. 선택한 코스는 모든 참가자에게 적용되며 경기 중에는 변경할 수 없습니다. 네 코스는 실제 대회의 코스 유형을 참고한 독자적인 레이아웃입니다. PC에서 차량을 쉽게 볼 수 있도록 코스 가로·세로와 한 바퀴 길이를 기존의 약 62%로 줄이고 도로 폭은 12m를 유지했습니다. 3바퀴에서 5바퀴로 늘려 총 주행 거리는 기존과 비슷하며, PC 공유 화면의 차량을 1.3배로 표시하고 번호를 키웠습니다. 휴대폰 차량 표시와 실제 충돌 판정은 원래 크기를 사용합니다. 나무·일반 건물 배경 없이 관중석·관객·조명탑이 둘러싼 경기장으로 구성하고, 코스 범위에 맞춰 카메라를 확대합니다. 서버 주행 판정과 PC·휴대폰 표시가 같은 코스를 사용합니다. 코스 및 경기장 장식 원본은 `game/circuits.json`, 재생성은 `node tools/Generate-Circuits.mjs`, PC 선택·맵 교체 검증은 `npm run verify:circuits`입니다. 수정 확인은 개발 게임을 다시 실행하세요.

기울기 감도는 모든 참가자에게 동일하며 중립에서 50도 기울였을 때 최대 조향입니다. 가속 페달을 누르면 엔진 반응이 점차 올라가고 고속에서는 가속력이 줄며, 페달을 놓으면 구름 저항·공기 저항·엔진 브레이크로 감속합니다. 브레이크는 전진 중 제동하고 완전히 정지한 뒤 0.35초 계속 누르면 후진합니다. 후진은 약 28km/h로 제한하고 속도계에 `R`을 표시합니다. 후진 중 엑셀은 먼저 제동한 뒤 전진하며 두 페달을 동시에 누르면 제동을 우선합니다. 입력이 끊기면 전진·후진 모두 멈춥니다. 잔디 위 추가 감속은 전진·후진 모두 초당 4m/s입니다. 벽은 벽 방향의 운동을 흡수하고 접촉 중 지속적인 마찰로 감속하므로 정면 충돌 후에는 후진으로 빠져나올 수 있습니다. 후진으로 체크포인트를 통과해도 바퀴 수가 올라가지 않습니다. 서버를 개발 실행으로 다시 켜고 휴대폰 페이지를 새로고침하면 적용됩니다.

레이싱 속도감을 강화했습니다. 엑셀 반응과 출발·고속 재가속을 빠르게 하고 전진 최고속도 제한을 324km/h로 높였습니다. 짧은 직선에서도 3초 이내에 200km/h를 넘도록 가속을 강화하고, 고속 조향 감도를 완화하며 제동력도 강화했습니다. 속도가 올라가면 1인칭 시야가 78→102도, 3인칭 시야가 68→92도로 부드럽게 넓어지고, 3인칭 카메라는 조금 낮아지며 뒤로 물러납니다. 서버를 다시 개발 실행하고 휴대폰 페이지를 새로고침하면 적용됩니다.

레이싱 검증: `npm test`, `node tools/verify-racing.mjs`(16명 동시 조작·실제 PC 렌더), `node tools/verify-menu.mjs`(두 게임의 메뉴 전환). 모델·서킷 원본은 `game/car-shapes.json`, `game/circuit.json`입니다. `tools/Generate-Racing-Models.mjs`에 참조 순서 1~6번의 차체·휠·창문·램프·흡기구를 각각 정의하며, `node tools/Generate-Racing-Models.mjs 1`처럼 한 모델씩 갱신합니다. 브라우저와 PC가 동일한 기하 데이터를 읽고, 메뉴 이미지는 `game/render_racing_cars.tscn`을 실행해 실제 모델로 생성합니다. 실제 폰의 센서 허용·조작감은 기기에서 별도로 확인해야 합니다.

`Start-DevGame.cmd`는 현재 작업 폴더의 소스로 게임·서버·터널을 실행합니다. 모바일 HTML/CSS/JS는 저장 후 휴대폰 새로고침으로 확인하고, 서버·Godot 소스는 게임을 종료하고 다시 개발 실행하면 반영됩니다. 패키지 빌드나 Git 업로드는 필요하지 않습니다. 개발용 Node.js·Godot는 필요하며 이 PC의 `.runtime/godot`를 재사용합니다. 같은 네트워크에서 개발하려면 `./tools/Start-DevGame.ps1 -Mode lan`을 사용합니다.

### push 시 자동 배포

`main`에 push하면 `.github/workflows/release.yml`이 테스트 → 자동 버전 생성 → Windows 게임·인스톨러 빌드 → 실제 설치·업데이트 검증 → GitHub Release 게시를 수행합니다. 버전은 `package.json`의 major.minor와 Actions 실행 번호를 조합한 `0.6.실행번호` 형식입니다. 태그나 패키지를 수동으로 만들 필요가 없습니다. 빌드가 성공하면 모든 파일을 draft Release에 먼저 올린 뒤 게시하므로 사용자는 완성된 패키지만 받습니다. 더 최신 커밋이 있으면 이전 빌드는 최신 배포로 게시하지 않습니다. 재실행은 같은 버전을 사용합니다. Actions 수동 실행은 main에서 동일하게 배포합니다. 저장소 설정에서 Actions의 Release 생성 권한이 허용되어야 합니다.

현재 저장소는 비공개입니다. 비공개 동안 일반 사용자의 온라인 설치·업데이트는 GitHub 접근 제한 때문에 불가능하며, 저장소를 공개로 전환하면 동일한 다운로드 주소로 사용할 수 있습니다. 계정 인증 정보를 게임에 넣지 않습니다. 기존 구매 서버 자동 배포 워크플로는 별도로 유지됩니다.

로컬 패키지는 `./tools/Build-Release.ps1`으로 `.runtime/releases`에 만듭니다. 로컬 확인은 `.runtime/releases/Playroom-Installer/Install-Playroom.cmd`로 시작합니다. 상위 폴더의 manifest와 게임 ZIP을 자동으로 찾으므로 이 경우 동봉된 패키지로 설치할 수 있습니다. Godot 4.6.2를 사용하며 필요한 엔진·템플릿·cloudflared는 공식 SHA256을 확인합니다.

로컬 배포 폴더의 게임 ZIP은 빌드가 성공하면 이번 빌드와 직전 빌드 두 개만 남기고 자동 정리합니다. 인스톨러 ZIP과 manifest는 유지합니다. 설치된 게임의 `versions` 폴더와 GitHub Release 이력은 이 정리 대상에 포함되지 않습니다. 정리 검증은 `powershell.exe -File tools/verify-release-retention.ps1`로 실행합니다.

검증: `npm test`, `powershell.exe -File tools/verify-install.ps1`(먼저 패키지 빌드), `node tools/verify-tunnel.mjs`(인터넷 연결 및 cloudflared 필요). Windows PowerShell 5.1 스크립트는 한국어 표시를 위해 UTF-8 BOM을 사용합니다. 개인 설치 경로·상태는 설치 폴더와 `%LOCALAPPDATA%/Playroom`에 저장하고 Git에 포함하지 않습니다.

## 게임 선택 메인 (2026-10-03)

PC 게임과 웹 메인이 여러 게임을 선택하는 PLAYROOM 화면으로 시작합니다. 바탕화면 게임 바로가기·개발 실행도 게임 선택 화면을 먼저 표시합니다. 4개 카드에서 게임을 고르면 오른쪽 설명과 입장 버튼이 바뀝니다. DIRT RALLY의 ‘대기실 입장’은 기존 포크레인 경기·QR 참가·팀 설정으로 연결됩니다. POCKET RACING, KITCHEN PANIC, PARTY MIX는 향후 게임을 위한 예시이며 현재 ‘준비 중’으로 표시합니다.

PC에서는 기존 실행 스크립트 또는 Godot F5로, 웹에서는 `http://localhost:3000`으로 확인하세요. 게임을 이미 실행 중이라면 다시 실행하고 웹은 새로고침하세요. 대기실의 ‘← 게임 선택’으로 목록에 복귀할 수 있습니다. 경기 중에는 이 버튼이 잠기므로 기존 ‘대기실로 돌아가기’로 경기를 마친 뒤 게임을 변경하세요. 게임 선택으로 돌아와도 서버의 참가자와 팀 설정은 유지됩니다. 웹 대기실은 `/#dirt-rally`로 바로 열 수 있습니다.

게임 카드는 정사각형입니다. 포크레인 이미지는 실제 경기의 `excavator()` 모델·도장 셰이더·관절·유압 실린더를 그대로 사용해 모래를 담은 버킷을 들어 올린 자세를 1024×1024로 렌더링한 것입니다. PC와 웹에 동일한 PNG를 포함했습니다. 웹 이미지 경로 추가는 Node 서버를 다시 실행해야 반영됩니다. 모델이 변경되면 Godot에서 `--path game res://render_menu_asset.tscn`을 실행하고 에디터에서 이미지를 다시 가져오면 카드 이미지를 갱신할 수 있습니다.

PC 메인은 `game/main_menu.gd`, 그림은 `game/menu_art.gd`, 기존 경기장은 `game/main.tscn`입니다. `--preview`, `--model-preview`, `--fixture=…`, `--capture` 검증 실행은 기존 경기장으로 바로 연결됩니다. 로컬 서버를 켠 상태에서 Godot의 `--headless --path game --script res://verify_menu.gd`로 선택·준비 중 잠금·대기실 연결·경기 중 변경 차단·복귀·재입장을 확인할 수 있습니다.

Godot 4 PC 공유 화면 + 휴대폰 웹 컨트롤러로 플레이하는 포크레인 팀 게임의 개발 버전입니다.

`Install-Playroom.cmd`로 설치한 뒤 `Start-Game.cmd` 또는 바탕화면 플레이룸을 실행하면 자동 업데이트 확인 후 게임을 실행합니다. 개발 중에는 `Start-DevGame.cmd`를 사용합니다. 기존 **1. 로컬 / 2. 운영 서버** 선택 메뉴는 `./Start-Playroom.ps1 -Mode Ask`로 명시적으로 열 수 있습니다. 기존 로컬 선택은 이전에 설정된 원격 접속 환경변수보다 우선합니다.

2. Godot에서 `game/project.godot`을 열고 F5로 실행합니다. 현재 검증에 사용한 버전은 Godot 4.7.2이며 실행 파일은 `.runtime/godot`에 있습니다. 개발 소스를 확인할 때는 `Start-DevGame.cmd`를 실행합니다. 일반 실행은 `Start-Game.cmd`를 사용합니다.

4. 휴대폰에서 이름을 입력합니다. 게임 내부에서 최대 8팀·30~900초를 설정하고 ‘적용 / 균등 배정’을 누릅니다. 최대 16명 목록에서 개별 팀 변경·참가자 제외가 가능하며 ‘경기 시작’으로 진행합니다.

실행 스크립트는 Node 서버를 백그라운드에서 실행하고 Godot 게임 창을 표시합니다. 기존 게임 서버가 있으면 재사용합니다. 이 PC에서 스크립트 실행 후 게임 프로세스의 응답과 서버의 앱·프로토콜 정보를 확인했습니다.

## 원격 서버 실행

인터넷 접속은 각자가 구축한 Node 서버의 HTTPS 주소를 입력해 사용합니다. PC 게임과 휴대폰은 모두 같은 서버에 연결합니다. 서버의 Nginx와 인증서로 HTTPS/WSS를 설정하는 방법은 `deploy/README.md`를 참고하세요.

- PC에서 `Start-RemoteGame.cmd`를 더블클릭하거나 `./Start-RemoteGame.ps1`을 실행합니다. 기존 원격 서버를 명시적으로 사용할 때는 `./Start-RemoteGame.ps1 -ServerUrl https://game.example.com`으로 실행합니다. 인자 없는 실행은 자동 터널 방식입니다.
- 게임 대기실에 표시되는 새 QR을 휴대폰으로 스캔합니다. 같은 Wi-Fi가 아니어도 참가할 수 있습니다.
- 진행자 키는 `%LOCALAPPDATA%/DirtRally/credentials`에 서버 주소별로 구분하고 Windows 계정으로 암호화해 저장합니다. 실행 경로에 관계없이 저장된 키를 자동으로 읽습니다. 키는 프로젝트 밖에 저장되어 Git과 배포 묶음에 포함되지 않습니다. 다른 PC에서는 자기 서버의 키를 처음 한 번 입력하거나 `DIRT_RALLY_HOST_KEY` 환경변수를 사용하세요.
- Godot 에디터에서 직접 실행할 때는 `DIRT_RALLY_SERVER_URL`과 `DIRT_RALLY_HOST_KEY`를 설정한 환경에서 에디터를 시작해야 합니다. 이미 열린 에디터에는 새 환경변수가 반영되지 않으므로 다시 실행하세요.
- 서버의 `PUBLIC_URL`은 QR과 참가 주소, PC의 `DIRT_RALLY_SERVER_URL`은 게임 연결 대상을 지정합니다. 원격 모드에서는 같은 공개 주소를 사용합니다. `HOST_KEY`가 진행자 인증을 담당하며 공개 `/config`에는 관리 키가 포함되지 않습니다.
- 원격 서버는 경기 하나를 운영합니다. 동시에 연결된 진행자들은 같은 경기와 참가자 목록을 관리합니다. 여러 독립 경기를 동시에 운영하는 기능은 없습니다.
- Node 서버를 재시작하면 방 코드·경기·참가자·채팅이 초기화됩니다. 게임은 재접속하지만 휴대폰은 새 QR로 다시 참가해야 합니다. 진행자 키는 서버 설정 파일에 보관하므로 재시작 후에도 유지됩니다.

서버 관리와 재배포 방법은 `deploy/README.md`를 참고하세요. 인터넷 지연이 추가되므로 현장 휴대폰에서 반응성을 확인해야 합니다.

`npm.cmd run verify:remote`는 실제 원격 서버에 16개 WSS 클라이언트와 Godot을 연결해 이동·관절·플레이어별 조작 권한·상태 수신·QR을 검증합니다. **경기를 시작하고 참가자를 제거하므로 운영 중인 경기에서는 실행하지 마세요.** 결과는 `.runtime/remote-live-report.json`과 `.runtime/remote-live-preview.png`에 저장됩니다. 실제 휴대폰 검증은 아닙니다.

## 조작

가로 전체화면 버튼은 전체화면 진입 후 가로 잠금을 한 번만 요청합니다. 전체화면 이벤트와 중복 요청하던 처리를 제거했습니다. 표준 API와 접두사 API를 확인하고, 전체화면을 지원하지 않으면 버튼을 ‘가로 사용 안내 / 화면 안내’로 표시합니다. 요청이 거절되면 직접 회전하는 방법과 QR 앱에서 Chrome·삼성 인터넷으로 여는 방법을 안내합니다. 아이폰에는 세로 잠금 해제와 홈 화면 웹앱 실행 방법을 안내합니다. 실제 Chrome의 전체화면 진입 및 지원·거절·미지원·접두사 API 경로를 검증했으며 갤럭시 실기 검증은 별도입니다.

2026-10-04: 전체화면 API가 Promise 없이 반환하거나 화면 전환보다 먼저 완료되는 경우에도 실제 전체화면 상태·이벤트를 확인한 뒤 가로 잠금을 요청합니다. 처리 중 중복 터치를 막고 전체화면·가로 잠금 응답이 없으면 각각 2.5초 후 버튼을 다시 사용할 수 있게 합니다. 구형 방향 잠금 API도 지원하며 실패 안내는 참가 전 가로 화면에서도 표시됩니다. 회귀 테스트 4개를 포함한 Node 테스트 25개, 실제 데스크톱 Chrome 전체화면 진입과 모바일 화면 크기 에뮬레이션을 통과했습니다. 실제 안드로이드 Chrome·삼성 인터넷 검증은 아직 필요합니다.

운영 서버에서 추가 확인한 원인: 기존 서버가 `/results.js`를 404로 응답해 컨트롤러 모듈 전체가 실행되지 않았고 버튼 클릭 핸들러도 등록되지 않았습니다. 서버를 재시작하지 않고 화면 파일만 배포할 수 있도록 모바일 결과 렌더러를 `controller.js`에 함께 포함했습니다. 공용 `results.js` 렌더러를 수정할 때는 이 포함본도 함께 갱신해야 합니다. `/results.js`가 없는 서버 조건에서도 컨트롤러 초기화와 실제 Chrome 전체화면 진입을 검증했습니다.

상단 채팅·상태 영역은 오른쪽 위 ‘상단 숨기기 / 상단 보이기’ 버튼으로 접고 펼칩니다. 접으면 확보한 높이에 맞춰 조작키가 커지며, 펼치면 기존 크기로 돌아옵니다. 선택은 같은 브라우저에서 기억합니다. 작은 가로 화면과 아이폰 주소창 높이를 가정한 브라우저 검증에서 크기 증가·복원·수평 정렬·새로고침 후 유지·채팅 동작을 확인했습니다. `deploy/Update-Controller.ps1`은 저장된 전용 SSH 키로 GitHub main의 커밋을 배포하며 비밀번호를 묻지 않습니다. 서버 코드 변경이 포함된 커밋이면 서버도 재시작합니다. 로컬 수정은 커밋하거나 업로드하지 않습니다.

아이폰 Safari로 접속하면 참가 전에 ‘Chrome에서 열기’와 ‘Safari에서 계속하기’ 두 가지 선택을 표시합니다. Chrome 앱 링크는 현재 접속 주소와 방 코드를 그대로 전달합니다. Chrome이 설치되지 않았다면 Safari 계속하기를 사용합니다. 두 브라우저 모두 주소창이 나타날 수 있습니다. Safari 계속하기는 같은 탭에서 기억하며 Chrome·Edge·Firefox 및 홈 화면 웹앱에서는 선택 안내를 생략합니다. 세로/가로 안내 배치와 URL 보존은 브라우저에서 검증했으며 실제 아이폰의 앱 전환은 아직 검증하지 않았습니다.

아이폰 Safari 주소창 대응 (2026-10-03): QR로 접속한 가로 컨트롤러는 `visualViewport`의 실제 보이는 높이와 노치·홈 표시줄 안전 여백을 반영합니다. 조작키는 고정된 화면 높이 차감 대신 남은 조작 영역을 측정해 크기를 정합니다. 높이가 360px 이하이면 채팅·상태 표시를 압축하고 하단 안내를 숨겨 조작 공간을 확보합니다. 화면 높이가 바뀌면 누르던 입력은 해제됩니다. QR로 연 Safari 탭의 주소창을 강제로 제거하지는 않습니다. 주소창 없는 실행은 Safari 공유 → 홈 화면에 추가 → 해당 아이콘 실행을 사용하며, ‘웹 앱으로 열기’ 항목이 있으면 켭니다. 서버 재시작으로 방 코드가 바뀌면 새 QR로 다시 접속해야 합니다. HTML·JS·CSS 변경만으로 반영되며 서버 재시작은 필요 없습니다. 원격 접속에는 해당 서버의 파일을 갱신해야 합니다. 기존 21개 테스트와 짧은 가로 화면·주소창 높이 변화·안전 여백·입력 해제·채팅 브라우저 검증을 통과했으며 실제 아이폰에서는 아직 검증하지 않았습니다.

휴대폰 참가 후 조작 화면 최상단에서 전체 채팅을 사용할 수 있습니다. 전송 버튼 또는 키보드의 전송으로 메시지를 보내고, 왼쪽 최신 메시지를 누르면 대화 내역을 펼칩니다. 최근 50개 메시지는 재접속 시에도 복원되며 서버 재시작 시 초기화됩니다. 메시지는 최대 200자, 전송 간격은 1초입니다. 입력창에 집중한 동안 조작은 멈춥니다. 채팅 서버 변경을 적용하려면 Node 서버를 다시 실행하고 휴대폰에서 새 QR코드로 접속하세요.

모바일 채팅은 Godot 게임 화면 왼쪽 아래에도 표시됩니다. `Start-Game.ps1`은 실행 중인 서버의 소스 버전을 확인하고 오래된 DIRT RALLY Node 서버를 최신 버전으로 재시작합니다. 이때 방 코드와 참가 정보가 초기화되므로 새 QR코드로 다시 접속하세요. 게임 대기실 연결·재접속과 모바일 채팅의 실제 Godot 표시를 `verify:lobby`에서 검증합니다.

ISO 형태의 두 조이스틱과 두 주행 레버를 사용합니다. 모든 축을 동시에 입력할 수 있습니다.

두 팔 조작 패드는 사각형 8방향 조이스틱입니다. 상하좌우와 네 대각선으로 방향이 고정되며, 대각선은 두 축을 같은 강도로 함께 움직입니다. 중심에서 미는 거리에 따라 강도는 연속적으로 달라지고, 손을 떼면 해당 패드의 두 축이 모두 0으로 돌아갑니다. 좌우 궤도 주행 레버는 기존의 위아래 조작을 유지합니다.

패드 위에 움직이는 부위를 표시한 그림이 있습니다. 왼손은 상부·암, 오른손은 붐·버킷, 양쪽 바깥 레버는 좌우 궤도를 담당하며 입력 중 해당 그림이 팀 색상으로 강조됩니다. 가운데 운전석 화면은 본인 차량의 운전석 위치와 상부 방향을 따라갑니다. 중앙 흙·팀 구역·다른 차량·본인 팔·버킷 흙을 같은 서버 상태로 표시합니다. `public/cab-view.js`의 Three.js 경량 3D 렌더링이며, PC Godot 화면의 영상 중계는 아닙니다. 폰 모델은 공유 화면 모델의 간략화된 형태입니다. WebGL을 사용할 수 없는 브라우저는 안내문을 표시하고 조작 패드는 유지합니다. 세로 화면과 숨겨진 탭에서는 운전석 렌더링을 중지합니다.

휴대폰 컨트롤러는 가로 화면 전용입니다. 참가하기 또는 전체화면 버튼을 누르면 지원 브라우저에서 가로 방향 잠금을 시도합니다. 브라우저가 잠금을 지원하지 않거나 거절하면 직접 휴대폰을 가로로 돌려주세요. 세로 화면에서는 회전 안내만 표시되고 조작이 중지됩니다. 휴대폰 자체의 화면 회전 잠금도 해제해야 할 수 있습니다.

버킷 이빨을 흙더미 가까이 낮추고 닫으면 최대 40 단위의 흙을 퍼담습니다. 흙을 실은 뒤 어디서든 버킷을 열면 내려놓습니다. 색상으로 표시된 정사각형 팀 구역 안에 내려놓으면 해당 팀의 점수가 됩니다. 구역 밖의 흙은 내려놓은 위치에 흙더미로 남으며 점수는 되지 않습니다. 어느 팀이든 다시 퍼서 구역으로 옮길 수 있습니다. 상대 구역의 흙을 훔쳐 구역 밖으로 옮겨 방해할 수 있고, 방해당한 팀도 그 흙을 되찾을 수 있습니다. 빈 바닥에서는 흙을 퍼담을 수 없습니다. 경기 종료 시 구역에 내려놓은 흙만 점수로 계산합니다. 동점은 공동 승리입니다.

### 포크레인 맵과 물길 경주

PC 대기실의 **맵 선택**에서 모래 쟁탈전 또는 폭포 물길 경주를 선택합니다. 웹 진행자 화면과 PC 게임 모두에서 선택할 수 있습니다. 맵 변경은 대기실에서만 가능하며 참가자와 방 코드를 유지합니다.

폭포 맵은 한쪽 끝의 폭포에서 반대쪽 끝의 목표선으로 물을 보내는 직사각형 맵입니다. 팀별 작업 구역을 나란히 배치하며 모든 팀이 같은 방향으로 물길을 팝니다. 팀마다 같은 길이의 땅과 목표선이 주어집니다. 버킷 이빨을 땅에 대고 닫아 흙을 파내세요. 버킷의 실제 위치, 높이, 방향을 따라 버킷 폭의 둥근 홈이 생깁니다. 같은 위치에서 계속 닫기만 하면 이미 판 부분에서 새 흙이 나오지 않으므로 붐을 더 낮추거나 암과 회전으로 새 부분을 이어 파야 합니다. 버킷이 차면 옆 풀밭에서 열어 비우세요.

흙 표면과 물 경계는 연속된 곡면으로 표시하며, 큰 사각 칸이 통째로 사라지지 않습니다. 물은 수면보다 낮고 폭포와 연결된 부분으로 조금씩 퍼집니다. 얕은 턱이나 끊긴 부분은 흐름을 막습니다. 목표선에 물이 먼저 도달한 팀이 즉시 우승하며 같은 서버 틱에 도착하면 공동 우승입니다. 제한 시간 동안 아무도 도달하지 못하면 무승부입니다. 한 명씩 겨룰 때는 참가자 수와 팀 수를 같게 설정하세요.

서버는 높이 표면을 보간하고 버킷의 곡면으로 잘라낸 부피만큼 적재량을 계산합니다. 물은 지형의 연결과 수면 높이를 따르는 게임용 흐름 시뮬레이션이며 실제 유체 역학 계산은 아닙니다.

### 세 번째 게임: FLAG STRIKE (FPS 깃발 쟁탈전)

게임 선택에서 세 번째 카드를 선택합니다. 기존 QR·방·휴대폰 연결을 그대로 사용하며 PC는 포크레인과 같은 비스듬한 조감 시점, 휴대폰은 캐릭터가 바라보는 방향의 1인칭 조준 화면입니다.

- PC의 고정 2.5D 화면 기준으로 왼손 방향키를 조작합니다. 휴대폰의 1인칭 화면은 상대를 중앙 십자가에 맞추는 데 사용합니다. 캐릭터가 이동하는 방향을 바라보고 그 방향으로 수평 발사하며 조준 높낮이 조작은 없습니다. 발사 버튼을 누르고 있으면 연사합니다.
- 캐릭터 앞의 방향 선으로 조준 방향을 표시합니다. 캐릭터가 바라보는 방향으로 가장 먼저 만나는 벽 또는 사람을 서버에서 판정합니다. 벽·아군 뒤의 상대는 맞지 않으며 아군 피해는 없습니다.
- PC와 모바일에서 발사 시 총구 섬광과 밝은 노란 탄 궤적을 표시합니다. 궤적은 서버 판정의 첫 벽·캐릭터에서 끝나며 해당 지점에 짧은 스파크가 나타납니다. 모바일 1인칭 소총에는 발사 반동도 표시합니다.
- 2–8팀, 최대 16명. 체력 100, 1발 피해 34, 발사 간격 0.25초. 사망 후 2초 동안 조작할 수 없고 사망한 위치에서 체력 100으로 부활합니다.
- 중앙의 노란 깃발에 접근하면 자동 획득합니다. 자기 팀 색상 진영으로 돌아가면 자동 운반 완료·팀 1점, 깃발은 중앙에 돌아옵니다. 운반자는 조금 느려집니다. 사망·접속 해제 시 깃발은 그 자리에 떨어집니다.
- 제한 시간 종료 시 깃발 운반 점수가 가장 높은 팀 우승, 동점은 공동 우승, 모두 0점이면 무승부. 처치 수는 개인 기록에만 포함됩니다.
- 새 경기는 깃발·점수·체력·개인 기록을 초기화합니다. 게임을 바꾸거나 재접속해도 참가자 ID는 유지합니다.
- 검증: `npm.cmd test`, `npm.cmd run verify:fps` (로컬 Godot 필요). 실제 휴대폰 기기·인터넷 지연은 별도 확인 대상입니다.

FPS 그래픽은 픽셀 질감의 군사 기지 스타일로 구성됩니다. 콘크리트 패널·나무 상자·감시탑·헬멧/방탄복 병사·1인칭 소총은 `game/fps-art.json`을 PC와 휴대폰에서 공유합니다. 원본 생성기는 `node tools/Generate-Fps-Art.mjs`이며 별도 이미지 서비스 없이 재생성할 수 있습니다. 깃발 운반 속도는 기본 속도의 80%이고, 처치 시 사망 위치에 떨어진 깃발을 살아 있는 다른 참가자가 회수할 수 있습니다.

FPS 이동 패드는 PC 카메라 위치 `(34,40,42)`를 기준으로 변환합니다. 위/아래/좌/우는 PC 화면에서 보이는 방향이며, 이동과 함께 캐릭터의 바라보는 방향도 바뀝니다. 이동 패드를 놓으면 즉시 멈추고 마지막 조준 방향을 유지합니다. 휴대폰에는 캐릭터의 1인칭 시야와 중앙 십자가를 표시하며, 십자가 방향으로 수평 발사합니다. 이동속도는 10m/s(깃발 운반 중 8m/s)이고 방향키 안쪽·바깥쪽 모두 같은 속도입니다. 바깥 원 회전·감속 기능은 제거했습니다.

깃발은 밝은 노랑/흰색의 큰 표식으로 표시되며, 바닥의 노란 원(반지름 2.5m) 안에서 벽에 가로막히지 않은 참가자가 자동 획득합니다. 운반 중 표식은 캐릭터 머리 위로 올라가고 획득 원은 숨겨집니다. 표식은 카메라 쪽을 향해 옆면 때문에 보이지 않는 상황을 줄입니다.
